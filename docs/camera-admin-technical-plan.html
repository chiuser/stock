P6S 摄像头管理后台一期方案

一期目标是把摄像头人脸库管理做成一个本地可用、用户友好、文档可追溯的后台。 本方案只讨论技术边界和产品交互，不进入代码实现。

部署边界
管理后台只在本地运行
远程服务器
只承担飞书通知发送能力
文档依据
P6S 官方公开文档 + 后续字段级确认

1. 需求复述

本地后台

摄像头登录与人脸库管理

本地后台用于配置并连接摄像头，管理摄像头内置的人脸库、人脸人员信息和图片。第一期覆盖脸库与人员记录的增删改查。

导入能力

手动新增与 CSV 批量导入

手动新增单条记录；CSV 批量导入作为本地后台的用户输入格式，导入时逐条转换为摄像头官方人脸人员接口。

不部署远程

管理后台不放到 qypower-prod

后台只绑定本地地址运行，避免摄像头账号、脸库操作入口暴露到公网。

远程 relay

远程只发飞书消息

远程服务器只负责接收通知请求并调用飞书，不做人脸库管理、不保存摄像头账号、不提供管理页面。

2. P6S 文档确认结论

下面只写已经从 P6S 公开文档确认的内容。字段级请求体如果公开页未给出完整 schema，不在方案里硬猜，后续 LLD 前必须通过 YApi 登录权限或真机接口验证补齐。

2.1 官方文档已确认

主题 文档结论 对一期方案的影响
脸库容量 最大 4 个脸库，每个脸库最多 10000 个人脸；组织可多层，最深 7 层。 一期默认只使用一个“会员人脸库”，不先做复杂组织树管理。
图片限制 文档说明在 YUV 4:2:0 情况下像素限制为 300x300，否则添加人员信息可能返回 4112 错误。 导入前必须做图片预检查和压缩/裁剪策略提示，页面不把 4112 暴露成裸错误码。
Owner 与安全码 /System/FrontDeviceOwnnerInfo 的 Ownner 是脸库拥有者；脸库增删改、人员增删改使用的 Ownner 字段实际是由拥有者和时间计算出的安全码，并与 SystemTime 一起传给设备。 后台首次初始化必须引导用户保存 Owner；所有写操作由后端自动生成安全码，前端不展示安全码。
脸库 CRUD 脸库接口包含 /FaceGroups/Create、/FaceGroups/Modify、/FaceGroups/Delete、/FaceGroups/QueryAll。 一期支持查看、创建、修改名称/阈值、删除脸库；删除脸库需要二次确认。
人员 CRUD 人员接口包含 /FaceGroup/UpdatePersonInfoAndFaceImage、/FaceGroup/ModifyPersonInfo、/FaceGroup/DeletePersonList、/FaceGroup/QueryPersonInfoListCount、/FaceGroup/QueryPersonInfoList。 一期人员新增/换图使用“人员信息和图片”接口；人员列表通过 count + list 查询；删除人员使用删除人员列表接口。
新增与更新区分 文档问答说明：/FaceGroup/UpdatePersonInfoAndFaceImage 中 FaceUUID 为空表示新增，不为空表示更新。 新增时不让用户填写 FaceUUID；更新时必须使用设备返回/查询到的 FaceUUID。
ID 来源 脸库 ID、组织 ID 由客户端生成；人脸信息 ID（FaceUUID）由设备生成。 CSV 里的会员编号只能作为本地业务编号，不能直接当作 FaceUUID；导入成功后需要保存会员编号与设备 FaceUUID 的映射。
查询安全码 文档说明脸库查询、组织查询、人员数量查询、人员列表查询不需要安全码。 页面列表刷新可以相对轻量；写操作仍必须走 Owner + SystemTime 生成安全码。

2.2 CSV 导入格式结论

在公开的 P6S 脸库管理文档中，没有发现“摄像头直接导入 CSV 文件”的官方接口或格式。官方能力是通过 HTTP 接口管理脸库与人员信息。因此一期不设计“把 CSV 原样上传给摄像头”，而是设计“本地后台读取 CSV，校验后逐条调用官方人员新增/更新接口”。

CSV 是我们的产品交互格式，不是摄像头原生格式。CSV 字段应服务用户理解，并在后端转换为摄像头接口所需的 XML 或请求体。

3. 推荐 CSV 格式

第一版 CSV 不暴露摄像头内部字段名，使用用户能理解的列。字段映射到摄像头接口的具体 XML 节点，将在 LLD 阶段基于接口详情或真机验证确定。 

member_id,name,group_id,image_path,note
3787108955784829,张三,members,/Users/congming/faces/3787108955784829.jpg,会员头像
CSV 列 必填 用户含义 技术处理
member_id 是 会员编号或业务编号 本地用于去重、导入报告和 FaceUUID 映射。不能默认等同摄像头 FaceUUID。
name 是 页面显示的人名 转换为摄像头人员信息里的姓名字段，字段名待接口详情确认。
group_id 否 目标人脸库 为空时使用后台当前选择的人脸库。对应官方文档中的 FaceGroupID / GroupID2 语义。
image_path 是 本地头像图片路径 后端读取图片，按文档限制做尺寸/格式校验，再随人员接口提交。
note 否 备注 仅用于导入报告和本地记录，是否写入设备取决于字段级文档确认。

不建议第一版 CSV 使用 FaceUUID 作为必填列。官方文档说明 FaceUUID 是设备生成；用户导入时填写它容易造成“看起来导入成功但后续无法更新/删除”的混乱。

4. 三层完整支持方案

一期不只做人员图片上传，而是完整支持 P6S 文档中的三层管理模型：脸库、组织、人员。UI 用用户能理解的“人脸库、分组、会员”组织页面，后端再映射到 P6S 的 GroupID2、OrganizationID、Layer1ID、FaceUUID 等字段。

4.1 三层模型与职责

层级 用户视角 主要能力 P6S 文档依据
脸库 一个门店或一类人员的人脸库，例如“会员人脸库”。 创建、查询、修改名称、修改阈值、删除。 /FaceGroups/Create、/FaceGroups/Modify、/FaceGroups/Delete、/FaceGroups/QueryAll
组织 脸库内的分组，例如“私教会员”“年卡会员”“临时访客”。 创建、查询树、重命名、移动或调整层级、删除。 /FaceGroup/OrganizationMemberAdd、/FaceGroup/OrganizationStructureTree、/FaceGroup/OrganizationMemberModify、/FaceGroup/OrganizationMemberDelete
人员 一个可被识别的人，通常关联会员编号、姓名和头像。 列表查询、手动新增、编辑资料、换照片、删除、CSV 批量导入。 /FaceGroup/UpdatePersonInfoAndFaceImage、/FaceGroup/ModifyPersonInfo、/FaceGroup/DeletePersonList、/FaceGroup/QueryPersonInfoListCount、/FaceGroup/QueryPersonInfoList

4.2 本地后台 API 设计

以下 API 是本地后台自己的接口，不直接等同 P6S 接口。这样 UI 可以保持稳定、用户友好，P6S 字段差异由后端适配层处理。

本地 API 用途 后端动作 UI 使用场景
GET /api/camera/connection 读取本地摄像头连接配置摘要。 只返回地址、是否配置账号密码、最近连接结果，不返回密码。 设置页顶部状态。
POST /api/camera/connection/test 测试摄像头是否可访问。 调用摄像头只读接口，返回“连接成功/失败原因”。 用户点击“测试连接”。
GET /api/face-owner 查看设备 Owner 初始化状态。 调用 /System/FrontDeviceOwnnerInfo GET。 初始化向导。
PUT /api/face-owner 首次写入或更新 Owner。 调用 /System/FrontDeviceOwnnerInfo PUT，并提示用户保存。 初始化向导，危险操作需确认。
GET /api/face-groups 查询所有脸库。 调用 /FaceGroups/QueryAll。 脸库列表、首页概览。
POST /api/face-groups 创建脸库。 生成或接收 group_id，计算安全码，调用 /FaceGroups/Create。 新建脸库弹窗。
PUT /api/face-groups/{group_id} 修改脸库名称或阈值。 计算安全码，调用 /FaceGroups/Modify。 编辑脸库。
DELETE /api/face-groups/{group_id} 删除脸库。 计算安全码，调用 /FaceGroups/Delete。 删除脸库二次确认。
GET /api/face-groups/{group_id}/organizations/tree 查询组织树。 调用 /FaceGroup/OrganizationStructureTree 并转换成 UI 树结构。 左侧分组树。
POST /api/face-groups/{group_id}/organizations 创建组织。 生成组织 ID，计算安全码，调用 /FaceGroup/OrganizationMemberAdd。 新增分组。
PUT /api/face-groups/{group_id}/organizations/{organization_id} 修改组织名称或层级。 调用 /FaceGroup/OrganizationMemberModify。 重命名或移动分组。
DELETE /api/face-groups/{group_id}/organizations/{organization_id} 删除组织。 调用 /FaceGroup/OrganizationMemberDelete，明确提示会删除下属人员。 删除分组二次确认。
GET /api/people 查询人员列表。 先调用 count，再调用 list，支持按脸库、组织、关键词分页。 人员列表、搜索。
POST /api/people 手动新增人员和头像。 FaceUUID 留空，调用 /FaceGroup/UpdatePersonInfoAndFaceImage。 新增人员表单。
PUT /api/people/{face_uuid} 修改人员资料。 优先调用 /FaceGroup/ModifyPersonInfo；若需同步换图，调用人员图片更新接口。 编辑人员抽屉。
POST /api/people/{face_uuid}/photo 替换人员头像。 携带已有 FaceUUID 调用 /FaceGroup/UpdatePersonInfoAndFaceImage。 换照片。
DELETE /api/people/{face_uuid} 删除单个人员。 调用 /FaceGroup/DeletePersonList，单条删除。 删除人员确认。
POST /api/imports/people-csv/preview CSV 预检。 解析 CSV、检查目标脸库/组织、图片、重复项，只生成预览，不写摄像头。 导入向导第 2 步。
POST /api/imports/people-csv/confirm 确认导入。 按预检结果逐条调用新增/更新接口，生成导入报告。 导入向导第 3 步。
GET /api/imports/{import_id} 查看导入结果。 读取本地导入任务状态和每行结果。 导入完成页、历史记录。

4.3 架构边界

本地

Camera Admin Local

  • 只监听本地地址，例如 127.0.0.1:8000。
  • 负责页面、登录、CSV 解析、图片校验、摄像头接口调用。
  • 摄像头账号密码只存在本地环境变量或本地加密配置中。
  • 本地保存导入任务、会员编号与 FaceUUID 映射、友好错误信息。
远程

Feishu Notify Relay

  • 部署在远程服务器，只用于飞书消息发送。
  • 不提供后台页面，不管理摄像头人脸库。
  • 接收陌生人事件或本地转发的抓拍图，并调用飞书接口。
  • 只保存必要的短期日志，避免长期留存人脸图片。

5. UI 详细设计

页面要面向普通使用者，而不是接口调试人员。默认不展示内部枚举、原始 XML、原始日志、错误码堆栈；这些只放在“高级诊断”或本地日志文件中。

清晰

用户语言

用“连接成功”“头像太大，需要压缩”“这 3 条需要补图片”替代 raw status、枚举值和错误码。

克制

少展示内部状态

首页只展示摄像头连接、人脸库数量、最近导入结果、通知状态。接口细节不进入主界面。

有设计感

有温度的工具感

采用卡片式布局、柔和背景、明确主操作按钮、导入进度条和结果摘要，让管理动作可控。

一期做

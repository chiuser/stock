P6S Event HTTP V2 + 飞书通知

摄像头人脸识别结果推送到服务器并转发飞书机器人

本方案建议使用摄像头主动推送的人脸识别事件 FaceReco 作为主链路： 摄像头完成识别与抓拍，服务器接收事件后按“匹配成功”和“未匹配成功”分流，再推送飞书通知。

1. 目标与范围

一期目标
  • 让摄像头通过 HTTP 主动把人脸识别事件推送到远程服务器。
  • 匹配成功时，每个独立识别事件都向飞书机器人发送匹配到的人员姓名、人员 ID、摄像头和识别时间。
  • 未匹配成功时，服务器把陌生人抓拍图保存到按日期创建的目录，并把保存位置与可点击查看链接发送到飞书。
  • 链路具备可验证、可回滚、可排障的最小闭环。
一期不做
  • 不把摄像头管理后台部署到远程服务器。
  • 不依赖摄像头内部识别记录查询接口作为主链路。
  • 不在本阶段实现完整人脸库管理 UI。
  • 不把真实飞书密钥、摄像头 Token 或服务器密钥写入仓库。
已确认决策
  • 首版沿用当前 FastAPI 服务 camera-face-guard，不另起一个事件桥接服务。
  • 摄像头事件入口采用现有风格：POST /api/p6s/events/<P6S_EVENT_SECRET>。
  • 陌生人图片查看采用“服务器保存文件 + 短期 token 链接”方案，首版不依赖飞书内嵌图片能力。
  • 远程访问先使用 http://82.156.198.180 打通链路，后续再升级域名和 HTTPS。
  • 匹配成功必须每次通知：不同识别事件即使是同一个人也都发送飞书；只有同一个事件被摄像头缓存重放时，才按事件去重避免重复通知。
  • 陌生人图片链接默认有效期 24 小时，原图文件默认保留 30 天。
  • 原有按文件名直接访问图片的接口不作为飞书消息链接使用，后续以 token 查看接口为准。
  • 首版不引入数据库，原始事件、处理记录、图片和 token 映射都先落到服务器文件系统。
实现参数
  • P6S_EVENT_NOTIFY_KNOWN_PERSON=true，表示匹配成功事件全部通知。
  • P6S_EVENT_IMAGE_LINK_TTL_SECONDS=86400，表示图片查看链接有效期为 24 小时。
  • P6S_EVENT_RETENTION_DAYS=30，表示事件图片默认保留 30 天。
  • P6S_EVENT_IMAGE_PUBLIC_BASE_URL=http://82.156.198.180/api/p6s/event-images/view，作为首版图片链接前缀。

2. 推荐事件选择

事件 用途 关键字段 结论
FaceReco 人脸识别事件，包含是否匹配到脸库人员的信息。 operator、info.matchNumber、personInfo、info.CaptureImage.picture、info.BackgroundImage.picture 主链路推荐。 文档说明 matchNumber=0 表示未匹配到目标，且陌生人时 personInfo 为空；匹配成功时则从 personInfo 提取人员姓名与 ID。
FaceSnapshot 人脸抓拍事件，能拿到人脸图和背景图。 operator、info.faceNumber、info.CaptureImage.picture、info.BackgroundImage.picture 备用链路。 如果真机暂时不触发 FaceReco，可以先用它验证 HTTP 推送与飞书图片链路，但它本身不能判断是否陌生人。
核心判断： 所有人脸识别通知都应优先基于 FaceReco。服务器先判断 operator == "FaceReco"， 再按 matchNumber 和 personInfo 分流：匹配成功则通知人员姓名与 ID；未匹配成功则保存图片并通知图片存储信息。 为避免误报，后续 LLD 里应把匹配成功和未匹配成功的真机样本都记录下来，确认 personInfo 字段的真实结构。

3. 总体链路

1

摄像头识别

摄像头本地启用人脸识别、人脸抓拍和事件推送联动。

2

HTTP 事件推送

摄像头通过 P6SEvent HTTP V2 把 FaceReco JSON 推到服务器。

3

服务器接收

服务端验签/鉴权、保存原始事件、解码抓拍图并返回 Ack。

4

识别结果分流

根据 matchNumber 与 personInfo 区分匹配成功和未匹配成功。

5

飞书分支通知

匹配成功发人员信息；未匹配成功保存图片并发送存储位置和查看链接。

匹配成功

只通知识别结果

飞书消息包含人员姓名、人员 ID、摄像头标识、识别时间、事件 ID。默认不保存额外陌生人图片，减少存储和隐私压力。

未匹配成功

保存图片并通知链接

服务器把抓拍图保存到按日期创建的目录，再生成一个短期有效的 HTTPS 查看链接。飞书消息同时展示服务器保存路径和可点击链接。

4. 摄像头侧配置方案

4.1 HTTP 服务器配置

使用 /System/HTTPEventServerConfigV2 配置摄像头要推送到的远程服务器。

字段 建议
Enable 设为 true，启用 HTTP 事件推送。
Protocol 先用 http 验证。离线文档标注 https 暂不支持，是否可用需真机确认。
Host 远程服务器公网域名或公网 IP。
URLPath 首版使用 /api/p6s/events/{P6S_EVENT_SECRET}，通过随机 secret 降低公网入口暴露风险。
Port 根据反向代理配置选择 80、443 或专用端口。
AuthMode 首轮联调可用 none，打通后切到 OAuth 或服务端自定义 Token 校验。
DeviceToken / Secret 仅在启用 OAuth 或设备认证能力确认后填写，真实值只放服务器密钥管理和摄像头配置中。
CacheEventEnable 建议 true，服务器短暂不可用时尽量减少事件丢失。

4.2 推送与识别能力启用

需要确保智能事件、人脸抓拍/识别，以及联动方式里的推送开关均已打开。

  • /System/AIEventCfg：启用 AI 事件上传，配置 Enable=true 和 HttpType=http。
  • /System/EventPushMode：确认人脸识别事件推送模式。字段 MQTTPushMode 是否影响 HTTP 合并推送，需要真机样本验证。
  • /AI/FaceSnapshotCfg：启用人脸抓拍，并确认 Trigger.Push.Enable=true。
  • /FaceReco/1/RecoRuleList：确认人脸识别规则、识别区域、联动推送策略是否生效。
安全取舍： 如果摄像头固件只能稳定推送 HTTP，建议由公网入口接收 HTTP，再在服务器内部转发到本机服务。 公网入口需要至少具备随机路径、Token 校验、IP 限制、请求体大小限制和日志审计。不要裸露一个无鉴权的通用事件入口。

5. 服务器侧模块设计

接收层

p6s_event_receiver

提供 POST /api/p6s/events/{P6S_EVENT_SECRET}，接收摄像头 JSON 事件，做基础鉴权、大小限制、结构解析和统一 Ack。

存储层

event_store

保存原始事件、事件索引、抓拍图文件、处理状态。第一阶段可先用文件系统，后续再接数据库。

分流层

recognition_result_router

只处理 FaceReco，依据 matchNumber 与 personInfo 分流到“匹配成功通知”或“陌生人图片保存”。

图片层

stranger_image_service

未匹配成功时保存抓拍图。优先使用事件内图片；如果真机只给图片记录 ID，再按记录 ID 从摄像头存储拉取图片。

链接层

image_link_service

把服务器真实文件路径映射为短期有效的 HTTPS 查看链接，飞书里点击链接时由服务器校验 token 后返回图片。

通知层

feishu_notifier

负责飞书机器人发送。匹配成功发送人员姓名与 ID；未匹配成功发送保存路径和图片查看链接。

运维层

observability

记录收到事件数、匹配成功数、陌生人事件数、图片保存结果、链接访问结果、飞书成功/失败、Ack 延迟和重复事件。

远程部署目标： 服务器代码需要部署到用户自有远程服务器，SSH 入口为 ssh qypower-prod， 公网 IP 为 82.156.198.180。本方案阶段只记录前置条件；实际初始化服务器、安装服务、修改防火墙和启动进程， 需要在 LLD 明确后再执行。

6. 事件处理细节

6.1 接收与去重

  • 请求体上限建议先设为 2MB 到 5MB，因为图片字段是 base64。
  • 原始 JSON 必须落盘或入库，便于复盘字段差异。
  • 去重键建议为 serialNumber + operator + eventId + pictureMd5。
  • 即使事件不是目标事件，也应返回成功 Ack，避免摄像头反复重试造成噪声。

6.2 识别结果分流

is_face_reco = event.operator == "FaceReco"
match_number = event.info.matchNumber
person_info_empty = event.personInfo is missing or empty

if is_face_reco and match_number > 0 and not person_info_empty:
    person = parse_matched_person(event.personInfo)
    send_feishu_known_person(person.name, person.id, event)
else:
    image_record = save_stranger_image(event)
    view_url = build_signed_image_view_url(image_record)
    send_feishu_stranger(image_record.storage_path, view_url, event)

LLD 阶段需要把真机样本中的 personInfo 空值形态和匹配成功字段名记录清楚，可能是空数组、空对象、空字符串或字段缺失。

6.3 匹配成功通知

  • 触发条件：operator == "FaceReco"、matchNumber > 0，且 personInfo 中能解析出人员信息。
  • 通知频率：每个独立匹配成功事件都发送飞书通知，不按人员维度静默或采样。
  • 去重边界：只对同一个事件的缓存重放或网络重试做幂等处理，避免同一事件重复通知。
  • 飞书标题建议：人脸识别成功。
  • 消息内容包含：人员姓名、人员 ID、摄像头序列号、识别时间、事件 ID。
  • 人员字段优先从 personInfo 中解析，字段名以真机样本为准；LLD 阶段需要固化映射。
  • 默认不保存额外图片，除非后续明确需要留存所有识别图片。

6.4 未匹配成功图片保存

  • 触发条件：operator == "FaceReco" 且 matchNumber == 0，或 personInfo 为空/缺失。
  • 图片来源优先级一：直接使用事件中的 info.CaptureImage.picture 人脸裁剪图。
  • 图片来源优先级二：如果裁剪图不存在，使用 info.BackgroundImage.picture 背景图。
  • 图片来源优先级三：如果真机事件只提供图片记录 ID 或图片路径，再由服务器调用摄像头接口从摄像头存储拉取。
  • 保存目录按日期创建，建议格式：/var/lib/camera-face-guard/p6s_events/strangers/YYYY-MM-DD/。
  • 文件名建议包含摄像头序列号、事件 ID 和图片 MD5，避免重名，例如 SN123_42_1bbd8864.jpg。

6.5 图片处理与校验

  • 优先使用 info.CaptureImage.picture，这是人脸裁剪图，适合通知。
  • 如果裁剪图不存在或解码失败，回退到 info.BackgroundImage.picture。
  • 兼容 data:image/jpeg;base64,... 和纯 base64 两种格式。
  • 用文件魔数校验 JPEG/PNG，不只相信字段名。
  • 如果存在 pictureMd5，保存后计算 MD5 做一致性校验。

6.6 可点击图片链接

飞书消息里不要直接暴露服务器真实文件路径，而是发送一个由服务器生成的 HTTPS 查看链接。

storage_path = /var/lib/camera-face-guard/p6s_events/strangers/2026-07-02/SN123_42.jpg
view_url = http://82.156.198.180/api/p6s/event-images/view/<token>
  • token 使用随机 token 映射服务器本地图片记录，服务端只保存 token 哈希。
  • 访问 GET /api/p6s/event-images/view/{token} 时，服务器校验 token、过期时间和文件存在性。
  • 校验通过后返回 Content-Type: image/jpeg 或 image/png，浏览器即可直接查看图片。
  • 建议默认链接有效期为 24 小时；如需长期追溯，可提供后台登录后查看的永久记录页。

6.7 摄像头 Ack

收到 FaceReco 后建议返回文档里的 FaceReco-Ack 结构，并把 pictureMd5 原样带回。

{
  "operator": "FaceReco-Ack",
  "info": {
    "personId": 0,
    "uniqueId": "",
    "pictureMd5": "from-event-if-present"
  },
  "result": {
    "errorNo": 0,
    "description": "ok"
  }
}

6.8 存储记录字段

未匹配成功时建议保存一条结构化记录，方便飞书通知、图片查看和后续排查。

  • event_id、camera_serial_number、event_time、received_at。
  • storage_path、file_name、image_md5、image_source。
  • view_token、view_url、expires_at、feishu_message_status。

7. 飞书通知方案

推荐首版

分支通知 + 服务器图片链接

使用飞书自定义机器人 webhook 发送富文本或卡片消息。匹配成功发人员信息； 未匹配成功发图片保存路径和可点击查看链接。

  • 匹配成功标题：人脸识别成功。
  • 匹配成功内容：人员姓名、人员 ID、摄像头序列号、识别时间、事件 ID。
  • 未匹配成功标题：发现未匹配人脸。
  • 未匹配成功内容：摄像头序列号、事件时间、事件 ID、服务器保存路径、图片查看链接。
增强版本

直接发送图片消息或富文本卡片

如果飞书机器人类型支持上传图片并获得 image_key，服务器可以先上传抓拍图，再发送包含图片的消息。 这个能力与机器人类型、应用凭证有关，需要在用户创建机器人后按实际文档确认。

  • 只有 webhook 的自定义机器人不一定能直接发送 base64 图片。
  • 如果需要图片内嵌展示，可能需要飞书开放平台应用凭证。
  • 因此首版先保留两种通知实现，运行时按配置选择。

7.1 匹配成功消息模板

标题：人脸识别成功
姓名：小明
人员 ID：3427976339944670
摄像头：SN123456
识别时间：2026-07-02 18:30:12
事件 ID：42

实际字段名以 FaceReco.personInfo 真机样本为准，LLD 中需要明确姓名和 ID 的映射。

7.2 未匹配成功消息模板

标题：发现未匹配人脸
摄像头：SN123456
识别时间：2026-07-02 18:35:01
事件 ID：43
保存位置：/var/lib/camera-face-guard/p6s_events/strangers/2026-07-02/SN123_43.jpg
查看图片：http://82.156.198.180/api/p6s/event-images/view/<token>

飞书展示“保存位置”用于运维追溯，真正可点击的是 HTTPS 查看链接。

点击查看图片的实现： 飞书里的链接指向服务器接口，而不是直接指向磁盘文件。服务器收到 GET /api/p6s/event-images/view/{token} 后校验 token、过期时间和文件权限， 再读取本地图片并返回图片内容。这样既能点击查看，又不会把服务器目录直接暴露到公网。
建议： 第一阶段先不要把飞书图片上传能力作为阻塞点。先完成“摄像头事件到服务器、匹配成功发人员信息、未匹配成功保存图片并生成可点击链接”的闭环。 等机器人类型确认后，再把通知升级为直接内嵌图片。
当前飞书机器人状态： 用户已提供自定义机器人 webhook 和签名秘钥。真实值已按仓库规则写入本地 .env.local 的 FEISHU_WEBHOOK_URL 与 FEISHU_WEBHOOK_SECRET，本文档和 git 中只保留变量名与用途， 不记录真实秘钥。

P6S_EVENT_IMAGE_LINK_SECRET 远程服务器密钥配置 生成和校验图片查看 token 的随机密钥。
P6S_EVENT_IMAGE_LINK_TTL_SECONDS 远程服务器环境变量 图片查看链接有效期，首版固定为 86400 秒。
P6S_EVENT_NOTIFY_KNOWN_PERSON 远程服务器环境变量 匹配成功是否通知；已确认必须设为 true。
P6S_EVENT_RETENTION_DAYS 远程服务器环境变量 事件图片与记录的默认保留天数，首版为 30。
P6S_EVENT_MAX_BODY_BYTES / P6S_EVENT_MAX_IMAGE_BYTES 远程服务器环境变量 限制事件请求体与图片大小，首版建议均为 5242880 字节。
CAMERA_SESSION_SECRET 本地与远程密钥配置 管理后台会话签名密钥，本地放 .env.local，远程放 /etc/camera-face-guard/app.env。
CAMERA_ADMIN_USERNAME / CAMERA_ADMIN_PASSWORD 本地与远程密钥配置 管理后台登录账号。本地调试和远程部署可分别配置，但不能进入 git。
P6S_CAMERA_HOST / P6S_CAMERA_USERNAME / P6S_CAMERA_PASSWORD 本地与远程密钥配置 摄像头 API 连接配置。管理后台本地运行时使用本地网络摄像头地址；远程事件服务不依赖它接收推送。
P6S_FACE_OWNER / P6S_FACE_GROUP_ID / P6S_FACE_GROUP_NAME 远程服务器环境变量 人脸库管理默认配置。Owner 本地真实值只写 .env.local，远程真实值只写远程 env 文件。
FEISHU_WEBHOOK_URL 远程服务器密钥配置 飞书机器人 webhook 地址。
FEISHU_WEBHOOK_SECRET 远程服务器密钥配置 如果飞书机器人开启签名校验，则必须配置。
FEISHU_APP_ID / FEISHU_APP_SECRET 远程服务器密钥配置 仅当后续采用“上传图片并发送 image_key”方案时需要。

本地真实配置仍遵守仓库规则，只能写入 .env.local；远程真实密钥只放远程服务器环境变量或密钥文件，不进入 git。

11. 风险、回滚与待确认项

主要风险
  • 摄像头固件可能不支持稳定 HTTPS，需要通过其他方式保护公网入口。
  • 飞书机器人是否能直接内嵌图片，取决于机器人类型和凭证能力。
  • base64 图片会放大请求体，服务端需要限制大小并防止内存占用过高。
  • FaceReco 事件可能需要正确启用识别规则和联动推送，否则只会有人脸抓拍。
  • 摄像头断网后缓存事件重放，可能造成重复通知，需要去重。
  • 图片查看链接如果长期有效或无鉴权，会导致陌生人抓拍图被外部访问；必须使用短期 token 或登录态保护。
  • 服务器磁盘会持续增长，需要设置图片保留策略，例如保留 30 天或按容量清理。
  • 远程服务器 82.156.198.180 如果直接开放 HTTP，需要额外做好随机路径、签名、限流和来源审计。
  • 如果公网 IP 后续变化、域名未绑定或安全组未开放端口，摄像头推送和飞书图片查看链接都会失败。
回滚方式
  • 将 /System/HTTPEventServerConfigV2.Enable 改为 false。
  • 将 /System/HTTPEventServerStatusV2.Status 改为 offline。
  • 关闭人脸抓拍或识别配置中的 Trigger.Push.Enable。
  • 远程服务器移除飞书 webhook 配置或停止事件接收服务。
已进入 LLD 约束： 服务名、远程目录、事件入口、图片 token 链接、飞书消息方式、匹配成功每次通知、陌生人图片 TTL 与保留期都已在 LLD 中固化。 剩余待真机确认项只影响字段兼容和边缘异常处理，例如 FaceReco 真机样本结构、图片字段是否稳定存在、 以及当前固件对 FaceReco-Ack 额外字段的容忍度。

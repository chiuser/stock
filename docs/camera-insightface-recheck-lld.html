LLD · InsightFace 二次识别

P6S 摄像头 InsightFace 二次识别与噪音过滤

本 LLD 严格基于 camera-insightface-recheck-plan.html 细化代码级实现。目标是在现有 P6S 事件链路中增加可开关的 InsightFace 二次判断层，首版以 shadow 模式记录并发送对比结论，不改变原飞书通知和入场统计。

一、实现边界

本次开发范围
  • 新增 InsightFace 二次识别服务和质量过滤服务。
  • 新增服务器侧 gallery embedding 构建脚本和加载逻辑。
  • 在 FaceReco 图片保存后、写库/通知前接入二次判断。
  • 新增 shadow 飞书机器人消息模板和发送函数。
  • 新增本地 POC、fixture 验证和部署校验步骤。
明确不做
  • 不修改摄像头抓拍、识别、推送、录像、脸库配置。
  • 不接入 RTSP 连续视频流。
  • 不训练模型，不做活体检测，不展示年龄性别。
  • 不把 buffalo_l.zip、.onnx、人脸图片、gallery embedding 提交 Git。
  • 不改主飞书机器人密钥、图片 token 链接规则和日报格式。

摄像头写入禁止：本 LLD 的所有开发、测试、部署验证均不得调用任何 P6S 摄像头写接口。若后续确实需要调整摄像头配置，必须另起方案并获得明确授权。

二、当前代码接入点

当前事件处理主入口在 app/services/p6s_events.py。现有逻辑已经保存双图、创建图片 token 链接、构建到场记录草稿并发送飞书。

位置 现状 本次接入方式
handle_event() 持久化原始事件、去重、按 operator 路由。 不改入口签名，不改变 heartbeat/ignored/duplicate 行为。
_handle_face_reco() 按 matchNumber/personInfo 路由为 known、stranger、parse_error。 不改变摄像头原始路由，只在各分支内增加 recheck 上下文。
_save_face_reco_images() 保存 BackgroundImage 和 CaptureImage，生成 token 链接。 InsightFace 只读取已保存的背景全图路径；背景图缺失时可回退人脸图。
_handle_known_face() 保存图片后立即构建 known 到场草稿并发主飞书。 保存图片后调用 run_face_recheck()。shadow 不改变原逻辑；filter 可停止写库/主通知；verify_and_override 仅按规则覆盖陌生人。
_handle_stranger() 保存图片后构建 stranger 到场草稿并发主飞书。 保存图片后调用 run_face_recheck()。verify_and_override 可把高置信命中改为会员/教练/员工。
_handle_parse_error() 保存图片后写 unknown_known 到场草稿并发送异常提醒。 可记录 recheck 结果并发送 shadow，对主异常处理不做身份覆盖。

二补充、已拍板结论

事项 结论 代码实现约束
首版上线模式 FACE_RECHECK_MODE=shadow 首版只发送 shadow 对比机器人消息，不改变主飞书、不改变 attendance_events 写入、不改变日报统计。
filter 模式过滤事件 不写入 attendance_events 只保存原始事件和处理记录。处理记录必须包含 face_recheck.status=filtered、face_recheck.reason、quality_flags，便于后续统计本地模型拦截数量和原因。
verify_and_override 允许把摄像头陌生人纠正为会员/教练/员工 仅当 gallery 命中超过 FACE_RECHECK_SIMILARITY_THRESHOLD 且领先第二名超过 FACE_RECHECK_SIMILARITY_MARGIN 时生效。摄像头 already-known 结果与 gallery 冲突时，不覆盖，只记录冲突。
Gallery 构建失败 单人失败不阻断全量构建 失败人员写入 build_report。如果小明等关键测试人员失败，脚本应以明确错误提示停下来，等待修正图片或输入后再继续。
其余默认项 按技术方案和本文档默认建议执行 CPU-only、buffalo_l、模型不进 Git、embedding 不进 Git、默认 fail-open、侧脸首版只 shadow 观测不强过滤。

  • 写入事件记录时字段名为 face_recheck。
  • shadow 机器人发送结果另写入 face_recheck_shadow_feishu，只保存 ok/status_code/text 摘要，不保存签名。

点位 设计
加载时机 第一次 FaceReco recheck 时 lazy-load。不开启则不引入启动耗时。
模型目录检查 加载前确认 det_10g.onnx、w600k_r50.onnx 至少存在；缺失返回 error 并 fail-open。
CPU 配置 FaceAnalysis(name=model_name, root=model_root, providers=["CPUExecutionProvider"])，prepare(ctx_id=-1, det_thresh=...)。
输入图片 优先 background_image_path；不存在时回退 capture_image_path；均不存在则返回 skipped。
读取方式 使用 cv2.imdecode(np.fromfile(...)) 或 cv2.imread()。读取失败返回 error 并 fail-open。

检测流程

def analyze_image(input: FaceRecheckInput, settings: FaceRecheckSettings) -> FaceRecheckResult:
    img = read_image(primary_path)
    faces = app.get(img)
    if not faces:
        return filtered_or_shadow("no_face")

    selected = select_face(faces, img_shape)
    quality = evaluate_quality(selected, img)
    match = gallery.match(selected.normed_embedding) if gallery_enabled else None
    return decide(input, quality, match, settings)

七、质量过滤规则

质量门控由 FaceQualityGate 负责。它输出 flags，不直接发飞书、不写 DB。业务是否抑制由 FaceRecheckDecision 根据模式处理。

flag 触发条件 shadow filter verify_and_override
no_face InsightFace 检测不到人脸。 记录并发 shadow。 抑制。 抑制。
low_det_score 选中人脸检测分数低于 FACE_RECHECK_DET_SCORE。 记录并发 shadow。 抑制。 抑制。
face_too_small 人脸框宽或高低于配置。 记录并发 shadow。 抑制。 抑制。
blurred 人脸区域 Laplacian 方差低于阈值。 记录并发 shadow。 抑制。 抑制。
side_face 关键点估算侧脸分数高于阈值。 记录并发 shadow。 首版不强制抑制，除非配置另开。 不参与身份覆盖，只记录。
multiple_faces 背景图中检测到多张脸。 记录人脸数。 默认不抑制，选最大且置信度最高的人脸。 只对选中人脸做 gallery 比对。

侧脸估算

  • 优先读取 InsightFace face 对象可能提供的姿态字段；若无字段，则使用五点关键点几何估算。
  • 几何估算只作为 shadow 观测指标，首版不作为强过滤条件，避免阈值未校准导致漏报。
  • LLD 不引入新模型做姿态识别，避免超出技术方案范围。

发送规则

  • FACE_RECHECK_ENABLED=false 时不发送。
  • FACE_RECHECK_MODE=shadow 时每条 FaceReco 都发送 shadow 对比消息。
  • filter 和 verify_and_override 时仍发送 shadow 消息，便于追踪实际干预。
  • shadow 发送失败不影响主链路，记录摘要后继续。
  • 消息中不得包含 webhook、secret、base64 图片、embedding 原始向量。

十二、异常处理与 fail-open

异常 处理方式 业务影响
模型目录缺失 返回 status=error、reason=model_missing。 FACE_RECHECK_FAIL_OPEN=true 时原链路继续。
InsightFace import 失败 捕获 ImportError，写入 error 类型。 原链路继续，shadow 可记录失败或跳过。
图片读取失败 返回 reason=image_read_failed。 原链路继续。
推理超时 返回 reason=timeout。 原链路继续；后续可调低模型或关闭 recheck。
gallery 文件缺失 质量过滤仍可用，gallery match 为 null。 verify_and_override 不进行身份覆盖。
shadow 机器人失败 记录 ok=false/status_code/text 摘要。 不影响主飞书和入场记录。

Gallery 构建验证

  • 构建脚本输出 gallery.npz、gallery_manifest.json、build_report。
  • 报告必须包含总人数、成功人数、失败人数、失败原因。
  • 对小明等已知人员抽样验证相似度命中。

事件流验证

  • fixture 覆盖 known + shadow：主飞书和 attendance 行为不变，记录包含 face_recheck。
  • fixture 覆盖 stranger + gallery 命中：shadow 下不覆盖，verify_and_override 下覆盖。
  • fixture 覆盖 no_face/blurred：shadow 下不抑制，filter 下抑制。
  • fixture 覆盖模型缺失/import 失败：接口不 500，原链路继续。
  • fixture 覆盖 shadow 机器人未配置：记录 skipped，不影响主链路。

生产 shadow 验收

  • 主机器人消息和 shadow 机器人消息的事件时间一致。
  • shadow 消息能看到摄像头结果、InsightFace 状态、质量分数、gallery 建议。
  • 主飞书通知数量、到场记录数量与启用前一致。

十五、回滚方案

  1. 最快回滚：远程设置 FACE_RECHECK_ENABLED=false，重启 camera-face-guard。
  2. 模式回滚：从 verify_and_override 或 filter 切回 shadow。
  3. 代码回滚：使用当前部署备份目录恢复上一版服务代码。
  4. 依赖回滚：若 InsightFace 依赖影响启动，回滚 requirements 和虚拟环境后重启。
  5. 模型回滚：模型目录可保留不动；关闭开关后不会读取。

本功能不写摄像头配置，因此回滚不涉及摄像头侧恢复。

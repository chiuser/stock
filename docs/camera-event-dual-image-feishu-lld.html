1. 现状与目标

现状

app/services/p6s_events.py 当前通过 _decode_event_image() 只返回第一张可用图，因此后续保存、链接、飞书通知都只有一张图片。

目标

对 FaceReco 事件并行处理 BackgroundImage 和 CaptureImage，为两张图片分别保存、分别生成 token 链接，并在飞书中分别展示。

2. 模块边界

模块 需要做的代码级调整 不得做的调整
app/services/p6s_events.py 新增双图解码结果结构；保存双图；将双图链接传给飞书模板；处理记录写入双图摘要。 不修改识别分组、陌生人判断、去重策略。
app/services/event_store.py 保存图片时允许传入 image_kind 或等价来源标识，使文件名区分 background 与 capture。 不改变事件目录根路径，不删除历史图片。
app/services/image_links.py 复用现有 create_image_link()，每张图创建一个 token 链接。 不改变 token 算法、不降低过期控制、不开放裸文件访问。
app/services/feishu.py 飞书模板增加 background_view_url 和 capture_view_url，只发送两个可点击链接。 不新增 webhook 配置，不打印 secret，不调用飞书图片上传接口。
app/services/attendance.py 调用方继续传单个主图；主图由事件层选择背景图优先。 不新增表字段，不引入 Alembic。

4. 图片解码与保存逻辑

4.1 解码函数

def _decode_event_images(info: dict[str, Any]) -> dict[str, DecodedEventImage]:
    targets = (
        ("background", "BackgroundImage"),
        ("capture", "CaptureImage"),
    )
    result = {}
    for kind, source in targets:
        decoded = _decode_named_event_image(info, kind=kind, source=source)
        if decoded:
            result[kind] = decoded
    return result

4.2 空图与异常处理

  • 字段不存在：记录为 missing，不抛异常。
  • base64 为空或解码后 0 字节：记录为 empty，不保存文件。
  • 非 JPEG/PNG：沿用 UnsupportedImageTypeError，记录为 unsupported_type。
  • 单张失败不影响另一张保存；两张都失败时沿用现有错误通知逻辑。

4.3 文件命名

20260704191512_I20F11AAA3D5133BCF1A1AE_629_capture_3fb9e605.jpg

命名只增加 background / capture 来源标识，其他规则沿用现有安全文件名和 md5 逻辑。

5. 事件流细节

1. handle_event() 仍先保存 raw JSON，并保持重复事件短路逻辑不变。
2. _handle_known_face()、_handle_stranger()、_handle_parse_error() 调用新的双图保存函数。
3. 双图保存函数返回 SavedFaceRecoImages，其中 primary() 优先返回背景全图。
4. 入场记录写库继续使用主图字段：stored_image=images.primary().stored_image。
5. 飞书通知传入两组链接：background_view_url、capture_view_url。
6. Ack 的 storedImage 保持为主图路径，优先背景全图，避免 Ack 结构扩大。

6.3 消息字段

字段 展示规则
查看背景全图 有 background_view_url 时展示。
查看人脸图 有 capture_view_url 时展示。
查看图片 仅作为旧参数兼容，不再优先展示。
拍板结论：本期飞书只发送两个 token 化可点击链接： “查看背景全图”和“查看人脸图”。不调用 upload_image()， 不发送飞书内联图片消息。

7. 数据库与日报兼容

  • 不新增 Alembic 迁移。
  • attendance_events.image_path、image_url、image_source 继续表示主图。
  • 主图选择规则：BackgroundImage 成功保存时使用背景全图；否则回退 CaptureImage。
  • 日报中已有图片链接字段将自然指向主图，即优先背景全图。
  • 双图详情只写入事件处理记录 JSON，后续如确有统计需求再单独设计数据库结构。

10. 开发步骤

  1. 补充双图 fixture：包含有效背景全图、有效人脸图，以及 recognizeImage 为空的真实形态。
  2. 在事件解析层新增双图解码函数，保留旧单图函数直到调用点完成切换。
  3. 调整图片保存文件名，加入 background / capture 标识。
  4. 将 _handle_known_face()、_handle_stranger()、_handle_parse_error() 切换为双图保存。
  5. 调整飞书 post payload，增加“查看背景全图”和“查看人脸图”。
  6. 保持飞书通知为文本卡片链接模式，不调用飞书图片上传函数。
  7. 更新验证脚本断言：两张图都保存、两个 token 都存在、飞书模板两个可点击链接都出现。
  8. 本地测试通过后，再由用户单独确认是否部署远程。

11. 回滚与安全

  • 回滚代码即可恢复单图逻辑。
  • 不做数据库迁移，因此没有数据库回滚脚本。
  • 不调用摄像头写接口，因此没有摄像头配置回滚。
  • 日志和飞书消息不得输出图片 base64、webhook、secret、Owner、摄像头密码。

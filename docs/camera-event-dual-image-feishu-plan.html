P6S 事件双图保存与飞书查看

本方案只解决一个问题：人脸识别事件中同时保存背景全图和人脸小图，并在飞书消息中提供两个可查看入口。 不修改摄像头配置，不调整识别算法，不新增去重策略，不重构数据库。

摄像头写配置、算法过滤、数据库迁移

1. 背景与目标

当前问题

当前服务端从 FaceReco.info 中按 CaptureImage、BackgroundImage、recognizeImage 的顺序选择第一张可用图。真实事件中 CaptureImage 常见为 128x128 小图， 飞书中看到的人脸图会很模糊。

目标结果

对每一条人脸识别事件，服务端分别保存 BackgroundImage 背景全图和 CaptureImage 人脸小图；飞书消息中提供“查看背景全图”和“查看人脸图”两个入口。

2. 范围边界

类别 本次做什么 本次不做什么
图片处理 解码、校验、保存 BackgroundImage 和 CaptureImage。 不做图片增强、压缩重采样、人脸质量评分、正脸过滤。
飞书通知 飞书消息展示两个用户可点击的图片链接：背景全图链接和人脸小图链接。 不新增飞书机器人，不改变 webhook、签名、密钥配置方式，不发送飞书内联图片消息。
服务端存储 两张图分别落盘，并分别生成 token 化查看链接。 不改变事件目录根路径，不迁移历史图片。
数据库 保留现有单主图字段语义：优先把背景全图作为主图写入现有记录。 不新增表、不新增列、不写 Alembic 迁移。
摄像头 只消费摄像头已推送的事件内容。 不调用任何摄像头写接口，不调整抓拍、识别、推送配置。
约束：如果某条事件缺少 BackgroundImage 或 CaptureImage，不得让整条事件失败； 有哪张就保存哪张，并在飞书中只展示可用图片入口。

3. 图片策略

字段 用途 保存要求 飞书展示
BackgroundImage 背景全图，用于查看现场整体画面和人员位置。 保存为 background 类型图片；优先作为事件主图。 展示为“查看背景全图”。
CaptureImage 人脸小图，用于查看摄像头实际裁剪识别的人脸区域。 保存为 capture 类型图片。 展示为“查看人脸图”。
recognizeImage 当前真实事件中可能为空图。 本次不纳入保存目标；保留在 raw 事件中。 不展示。

4. 数据流

1. 摄像头推送 FaceReco 事件到服务器，服务器照常保存 raw JSON。
2. 事件处理模块从 info.BackgroundImage 和 info.CaptureImage 中分别提取 base64 图片。
3. 服务端校验图片必须是 JPEG 或 PNG，空图、无效 base64、非图片内容单独标记为不可用。
4. 可用图片分别保存到事件图片目录，并生成各自 token 化查看链接。
5. 入场记录继续按现有流程写库；单主图字段优先记录背景全图链接，缺失时回退到人脸小图。
6. 飞书消息保留原有身份、姓名、事件时间、事件 ID 等字段，并新增两个图片入口。

6. 影响面

模块 影响
app/services/p6s_events.py 事件图片解析从单图改为双图；通知参数增加背景图和人脸图链接。
app/services/event_store.py 图片文件名需要带来源标识，避免同事件双图文件名冲突。
app/services/feishu.py 飞书消息模板增加两个图片入口；保留原有标题和身份字段。
app/services/attendance.py 只使用现有单主图字段，不新增数据库结构；主图选择逻辑改为背景图优先。
测试脚本与 fixtures 补充双图事件样例，验证两张图均保存、均生成链接、飞书模板字段正确。

7. 风险与处理

风险 处理方式
图片体积增大 沿用现有最大图片大小限制；超限图片标记失败，不影响事件整体处理。
飞书消息过长 只新增两个链接，不展开 base64，不在消息中打印 token hash 或内部 JSON。
只有一张图可用 只展示可用链接；不可用图片写入处理记录，便于排查。
历史日报主图变化 不迁移历史数据；新事件主图改为背景全图优先，符合“更清晰查看”的目标。

8. 回滚方式

  • 代码回滚到上一版本后，事件处理将恢复为单图逻辑。
  • 已经保存的双图文件不需要删除，不影响旧版本读取已有单主图记录。
  • 不涉及数据库迁移，因此不需要执行数据库回滚。
  • 不涉及摄像头配置，因此不需要恢复摄像头参数。

9. 验证方式

  • 本地 fixture 验证：构造同时包含 BackgroundImage 和 CaptureImage 的事件，确认保存两张图片。
  • 链接验证：确认两张图片各自生成 token 链接，且可通过 /api/p6s/event-images/view/{token} 访问。
  • 模板验证：确认已匹配人员和陌生人飞书消息都包含“查看背景全图”和“查看人脸图”。
  • 兼容验证：缺少其中一张图时事件不失败，飞书只显示可用入口。
  • 安全验证：日志、处理记录、飞书消息不输出 base64 正文、webhook、secret、Owner、摄像头密码。

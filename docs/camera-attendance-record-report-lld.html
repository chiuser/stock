Camera Face Guard / LLD

入场记录、日报与飞书去重

基于 camera-attendance-record-report-plan.html 的代码级设计文档。本 LLD 只覆盖本期需求：每条人脸识别入场落库、非陌生人 2 小时提醒去重、陌生人每次提醒、每天 22:00 写库并发送飞书日报、PostgreSQL + Alembic 迁移管理。

状态
待 Review，未开发
数据维护
Alembic + PostgreSQL
摄像头边界
不写摄像头配置、不改脸库

1. 设计边界

本期实现
  • 所有真实 FaceReco 事件写入 attendance_events。
  • 会员、教练、员工、已匹配但未知分组、陌生人五类身份均可记录。
  • 会员、教练、员工和未知已匹配身份按同一人 2 小时内不重复飞书提醒。
  • 所有 FaceReco 事件都尽量保存图片并生成 token 链接，覆盖会员、教练、员工、未知已匹配身份和陌生人。
  • 陌生人每次识别都发送飞书；非陌生人仍按 2 小时去重策略决定是否发送飞书。
  • 每天 22:00 按日期统计日报，写入 daily_attendance_reports，并发送飞书日报。
  • 日报标题固定为“每日入场情况统计”，内容按照日报快照字段组织。
本期不实现
  • 不做人脸向量、陌生人聚类或“同一陌生人”合并。
  • 不自动回填历史 raw JSON。
  • 不做复杂 BI 看板；首版只提供日报 JSON、快照和飞书日报。
  • 不改变摄像头抓拍、识别、推送、脸库、阈值等任何设备侧配置。
稳定性硬约束：摄像头 HTTP 回调必须尽快返回 Ack。PostgreSQL 异常不能导致摄像头回调 500，也不能阻塞已有 raw JSON 落盘、图片保存和当前飞书通知链路。DB 不可用时采用 fail-open：保留现有文件落盘和飞书发送能力，但本次无法执行 2 小时 DB 去重。

4. Alembic 迁移设计

迁移原则

所有表结构、索引、约束都由 Alembic 版本文件管理。禁止在应用启动时自动建表，避免线上不可控变更。

上线命令

部署后由运维脚本或手工执行 alembic upgrade head。迁移必须先于开启 ATTENDANCE_DB_ENABLED=true。

回滚原则

代码回滚不自动删表。只有明确要回滚表结构时，才执行 alembic downgrade -1，且需要先备份数据。

4.1 alembic/env.py 核心逻辑

from __future__ import annotations

import os
from logging.config import fileConfig

from alembic import context
from sqlalchemy import engine_from_config, pool

config = context.config
if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = None

def database_url() -> str:
    url = os.environ.get("DATABASE_URL", "").strip()
    if not url:
        raise RuntimeError("DATABASE_URL is required for Alembic migrations")
    if url.startswith("postgresql://"):
        url = url.replace("postgresql://", "postgresql+psycopg://", 1)
    return url

def run_migrations_online() -> None:
    section = config.get_section(config.config_ini_section) or {}
    section["sqlalchemy.url"] = database_url()
    connectable = engine_from_config(
        section,
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )
    with connectable.connect() as connection:
        context.configure(connection=connection, target_metadata=target_metadata)
        with context.begin_transaction():
            context.run_migrations()

run_migrations_online()

5.3 字段约定

字段约定
person_typemember、coach、staff 来自本地 GroupID2 映射；匹配成功但无法映射时为 unknown_known；未匹配为 stranger。
person_ref_id已知人员使用 FaceUUID；陌生人使用 stranger_id 转字符串；解析错误但属于已匹配未知身份时使用 unknown:<event_dedupe_key>。
delivery_count同一 event_dedupe_key 被摄像头重复投递时自增。重复投递不产生新的入场统计。
should_notify策略层计算结果，不代表飞书一定发送成功。发送结果看 feishu_notifications.send_status。
image_token_hash沿用现有 token 链接机制，不保存 token 明文。所有 FaceReco 事件只要成功提取图片，都应写入 image_path、image_url 和 token hash。

6. 领域对象

不引入 ORM model。服务层用 dataclass 传递明确字段，仓储层用 SQLAlchemy text() 执行 SQL。

from dataclasses import dataclass
from datetime import datetime

@dataclass(frozen=True)
class AttendancePerson:
    person_type: str
    person_ref_id: str
    name: str
    camera_person_id: str | None
    face_group_id: str
    face_group_name: str

@dataclass(frozen=True)
class AttendanceImage:
    source: str
    path: str
    url: str
    token_hash: str | None

@dataclass(frozen=True)
class AttendanceEventDraft:
    event_dedupe_key: str
    camera_serial_number: str
    camera_event_id: str
    event_time: datetime
    received_at: datetime
    person: AttendancePerson
    match_number: int | None
    image: AttendanceImage | None
    raw_event_path: str

@dataclass(frozen=True)
class NotifyDecision:
    should_notify: bool
    suppressed: bool
    suppressed_reason: str
    reference_event_id: int | None

@dataclass(frozen=True)
class AttendanceInsertResult:
    event_id: int
    inserted: bool
    delivery_count: int
    notify_decision: NotifyDecision

camera_person_id 来自摄像头事件中的 personId。真实设备可能返回 16 位级别的人员 ID，例如 3427976339944670，超过 PostgreSQL integer 范围。该字段只用于追踪设备侧原始 ID，不参与数值计算，因此数据库和领域对象都必须按 text / str 保存。

7. 事件流接入

7.1 总流程

camera.py 接收 /api/p6s/events/{secret}，校验 secret 和 body 大小。
p6s_events.handle_event() 生成 EventIdentity 并先落 raw JSON。
如果是 heartbeat 或非 FaceReco，保持现有逻辑，不写入入场表。
如果是重复投递，尝试执行 attendance_repo.increment_delivery_count()，然后返回现有 Ack，不发飞书。
所有 FaceReco 分支先尝试从 CaptureImage、BackgroundImage 或 recognizeImage 保存图片、创建 token 链接。
如果是已知人员，解析 MatchedPerson 和角色，并带上图片信息构造 AttendanceEventDraft。
如果是陌生人，构造 AttendanceEventDraft 时同样带上图片路径和 token 链接。
attendance.record_event() 在事务中 upsert 人员、按独立开关决定是否计算 2 小时去重、插入入场事件。
如果 should_notify=true，调用现有 feishu.py 发送；如果被抑制，则不调用飞书。
写入 feishu_notifications：发送成功、失败或 suppressed 都要有记录。
写现有 processing record，返回摄像头 Ack。

7.5 写库开关与去重开关

ATTENDANCE_DB_ENABLED 和 ATTENDANCE_NOTIFY_DEDUP_ENABLED 必须分离。前者只决定是否写入 PostgreSQL；后者只决定非陌生人是否执行 2 小时提醒去重。

if not settings.attendance_db_enabled:
    # 不写 attendance_events，不查询去重窗口。
    # 保持旧行为：known/stranger 按事件本身发送飞书。
    return AttendanceFallbackResult(should_notify=True)

with transaction() as conn:
    upsert_person_or_insert_stranger(conn, draft)

    if draft.person.person_type == "stranger":
        decision = NotifyDecision(should_notify=True, suppressed=False)
    elif not settings.attendance_notify_dedup_enabled:
        # 仍写库，但不做 2 小时提醒抑制。
        decision = NotifyDecision(should_notify=True, suppressed=False)
    else:
        # 只有这里才查询 2 小时窗口和 advisory lock。
        decision = compute_known_person_dedup_decision(conn, draft)

    return insert_attendance_event(conn, draft, decision)

8.3 同一人员去重锁

为了避免并发回调同时判断“过去 2 小时没有提醒”导致重复发飞书，只有当 ATTENDANCE_NOTIFY_DEDUP_ENABLED=true 且人员不是陌生人时，才对同一人员加 PostgreSQL 事务级 advisory lock。关闭提醒去重时不需要执行此 SQL。

select pg_advisory_xact_lock(
  hashtext(:person_type || ':' || coalesce(:person_ref_id, ''))
);

8.4 查询 2 小时内最近一次已提醒事件

仅当 ATTENDANCE_NOTIFY_DEDUP_ENABLED=true 时执行。

select event_id, event_time
from attendance_events
where person_type = :person_type
  and person_ref_id = :person_ref_id
  and person_type <> 'stranger'
  and should_notify = true
  and notification_suppressed = false
  and event_time >= (:event_time - (:window_seconds * interval '1 second'))
  and event_time < :event_time
order by event_time desc
limit 1;

select
  count(*) filter (where person_type = 'member') as member_entries,
  count(*) filter (where person_type = 'coach') as coach_entries,
  count(*) filter (where person_type = 'staff') as staff_entries,
  count(*) filter (where person_type = 'stranger') as stranger_entries,
  count(*) filter (where person_type = 'unknown_known') as unknown_known_entries,
  count(*) filter (where should_notify = true) as notification_should_send_count,
  count(*) filter (
    where exists (
      select 1
      from feishu_notifications n
      where n.attendance_event_id = attendance_events.event_id
        and n.send_status = 'sent'
    )
  ) as notification_sent_count,
  count(*) filter (where notification_suppressed = true) as notification_suppressed_count
from attendance_events
where event_time >= :day_start
  and event_time < :day_end;

9. 提醒决策

场景DB 记录飞书行为
会员/教练/员工首次或 2 小时外识别should_notify=true、notification_suppressed=false，同时写入图片路径和 token 链接发送对应标题：会员/教练/员工入场提醒，并包含“查看图片”链接。
会员/教练/员工 2 小时内重复识别should_notify=false、notification_suppressed=true、suppressed_reason=known_person_2h_window，仍写入图片路径和 token 链接不发送飞书，写 feishu_notifications.send_status=suppressed。
ATTENDANCE_NOTIFY_DEDUP_ENABLED=false仍写入 attendance_events；非陌生人重复识别也保持 should_notify=true、notification_suppressed=false非陌生人每次都发送飞书。此开关不影响 ATTENDANCE_DB_ENABLED。
匹配成功但无法映射分组person_type=unknown_known，同样执行 2 小时去重，并写入图片路径和链接2 小时外发送“人员入场提醒”，并包含“查看图片”链接。
陌生人每次写 strangers 和 attendance_events，should_notify=true每次发送“发现陌生人入场”，包含图片查看链接。
摄像头重复投递同一 dedupe key不新增入场，只自增 delivery_count不重复发送。
ATTENDANCE_DB_ENABLED=false不写 DB，也不查询去重窗口fail-open，沿用现有飞书发送行为；这个开关只影响写库，不代表去重策略开关。
DB 不可用不写 DB，processing record 记录 DB 错误摘要fail-open，沿用现有飞书发送行为；此时无法依赖 DB 执行 2 小时去重。

11.1 日期边界

日报按 ATTENDANCE_REPORT_TIMEZONE 计算自然日边界。服务层把日期转换为带时区的 day_start 和 day_end，SQL 只做范围查询，避免依赖 PostgreSQL session timezone。

def day_range(report_date: date, timezone_name: str) -> tuple[datetime, datetime]:
    tz = ZoneInfo(timezone_name)
    start = datetime.combine(report_date, time.min, tzinfo=tz)
    end = start + timedelta(days=1)
    return start, end

11.2 日报生成函数

def generate_daily_report(
    report_date: date,
    *,
    save_snapshot: bool,
    send_feishu: bool,
) -> DailyReportResult:
    summary = attendance_repo.fetch_daily_summary(day_start, day_end)
    strangers = attendance_repo.fetch_daily_strangers(day_start, day_end)
    snapshot = attendance_repo.upsert_daily_report(summary, strangers)
    feishu_result = None
    if send_feishu:
        payload = build_daily_report_post(snapshot)
        feishu_result = feishu.send_post_payload(payload)
    return DailyReportResult(snapshot=snapshot, feishu=feishu_result)

11.4 22:00 定时调度

首版使用服务内轻量调度，避免额外引入定时框架。当前部署为单实例服务时不会重复发送。如果未来服务改成多实例，需要改成 systemd timer、cron 或独立 worker，并使用 DB 锁保证单次执行。

async def daily_report_loop(stop_event: asyncio.Event) -> None:
    while not stop_event.is_set():
        next_run = compute_next_run_time(
            time_text=os.environ.get("ATTENDANCE_DAILY_REPORT_TIME", "22:00"),
            timezone_name=os.environ.get("ATTENDANCE_REPORT_TIMEZONE", "Asia/Shanghai"),
        )
        await wait_until(next_run, stop_event)
        if stop_event.is_set():
            break
        report_date = next_run.date()
        await asyncio.to_thread(
            reports.generate_daily_report,
            report_date,
            save_snapshot=True,
            send_feishu=True,
        )
